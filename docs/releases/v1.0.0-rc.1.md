# BinVault 1.0.0-rc.1 release candidate

BinVault organizes household inventory by hierarchical Locations and Containers, with optional Categories and metadata for standard items, assets, consumables, and documents. This **release candidate** is intended for the owner's first private, local single-operator home installation, not a final v1.0.0 release or a public Internet service.

The RC includes inventory/container lifecycle, photos, search, dashboard insights, Activity & History, a responsive desktop/mobile shell, portable ZIP backup and validation, stopped-app recovery, production checks/init/readiness/start, health/readiness probes, and Node 22/24 CI. See [Production operation](../PRODUCTION.md) for the first install and [Backup and recovery](../BACKUP_RECOVERY.md) before trusting data to it.

This RC is for dogfooding a whole-home inventory. Report reproducible issues with RC version, steps, expected/actual behavior, severity, and data-safety impact; see [Dogfooding](../DOGFOODING.md). Keep household addresses, serial numbers, photos, documents, and backup ZIPs out of public GitHub issues.

Limitations: no authentication, multi-user/public Internet deployment, QR, notifications, maintenance workflows, document upload center, non-photo attachments, bulk/pagination, offline PWA, cloud sync, or scheduled/encrypted backups. SQLite and media files are not one atomic transaction. Backups coordinate one app process; interrupted media changes may leave orphans; restore requires the app stopped and validates bounded ZIP sizes.

An older annotated `v1.0.0` tag points to earlier history and its GitHub Release contains unrelated CJEF notes. It is **not** this BinVault production RC or a valid current BinVault final v1 release. The owner will decide how to correct that artifact before any final v1.0.0 release.
