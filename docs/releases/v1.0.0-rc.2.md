# BinVault 1.0.0-rc.2 release candidate

BinVault 1.0.0-rc.2 supersedes rc.1 for continued private, local single-operator home dogfooding. It retains the rc.1 inventory, container, settings, photo, search, dashboard, Activity & History, backup/recovery, production runtime, health/readiness, responsive shell, and Node 22/24 CI scope.

## Why rc.2 exists

Initial rc.1 dogfooding exposed a release-blocking dark-theme foreground/contrast defect. BinVault's application surfaces are intentionally dark, but the application root did not declare the semantic dark theme. Components relying on inherited semantic foreground tokens could therefore render near-black text on dark backgrounds, including typed form and search text.

Rc.2 declares the dark theme at the application root and adds regression coverage for that root theme contract. Manual validation covered Dashboard Global Search, Settings/reference-data forms, and inventory forms and controls.

There are no schema, migration, data-model, backup-format, restore-protocol, or production-storage changes between rc.1 and rc.2.

This release candidate remains intended for the owner's private home installation and dogfooding, not a final v1.0.0 release or a public Internet service. See [Production operation](../PRODUCTION.md), [Backup and recovery](../BACKUP_RECOVERY.md), and [Dogfooding](../DOGFOODING.md).

Limitations remain unchanged from rc.1: no authentication, multi-user/public Internet deployment, QR, notifications, maintenance workflows, document upload center, non-photo attachments, bulk/pagination, offline PWA, cloud sync, or scheduled/encrypted backups. SQLite and media files are not one atomic transaction. Restore requires the application stopped.

An older annotated `v1.0.0` tag still points to unrelated earlier repository history and its GitHub Release contains unrelated CJEF notes. It is not a valid current BinVault final v1 release and must be deliberately resolved before final v1.0.0.
